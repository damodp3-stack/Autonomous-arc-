# Project Context

**Product Name:** Autonomous Arc
**Product Vision:** A mobile-first AI coding assistant that empowers users to build, iterate, and deploy full applications through natural language directly from their mobile devices.
**Core Purpose:** To lower the barrier to software development by providing a portable, isolated, and intelligent project workspace.
**Problem Being Solved:** Traditional coding requires desktop environments and complex setups. Autonomous Arc brings the power of an AI-driven IDE to mobile, making software creation accessible anywhere.
**Target User Experience:** A clean, modern UI (High Density theme) with a chat-based interaction model, seamless context switching between projects, and clear visibility into AI actions.
**Long-term Product Goal:** A fully autonomous agent capable of analyzing repositories, proposing architecture, writing code, and triggering cloud builds via mobile input.
**Product Principles:** Modular architecture, mobile-first design, transparent AI operations (user review), extensible integrations (multiple AI providers).
**Major Planned Capabilities:** Files & Code workspace, multi-provider AI support, GitHub integration, media/assets generation, token tracking, and APK/cloud builds.
**Mobile-first Strategy:** Utilizing adaptive Compose layouts, quick prompt entry fields, and intuitive project list navigation to ensure comfortable use on small screens.

## Core Experience (AI-Assisted Development Concept)

The ultimate intended workflow for Autonomous Arc is:
1. **User Prompt:** User describes a feature or app.
2. **AI understands project:** AI retrieves the isolated project metadata.
3. **AI analyzes existing files:** AI reads the current workspace context.
4. **AI proposes changes:** AI generates a diff or plan.
5. **User reviews:** The user inspects the proposed changes in the mobile UI.
6. **Changes are applied:** Approved code is injected into the project files.
7. **Version is saved:** The changes are committed or versioned.
8. **Project can be tested/built:** The user triggers a cloud or local build to preview the app.

*(Note: Distinguish this long-term vision from the current product state, which is currently focused on Phase 1 foundational project and chat management.)*
